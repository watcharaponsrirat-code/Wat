## ลดคำขอเมื่อเปิดหน้าครู (24 ตุลาคม 2569)

รุ่นใน workspace ส่งห้องที่ได้รับสิทธิ์และรายชื่อนักเรียนหน้าแรก 25 คนมาพร้อมผล Login ของครู/แอดมิน จึงเปิดรายชื่อได้ด้วยคำขอเดียว จากเดิม Login → อ่านห้อง → อ่านรายชื่อ นักเรียนไม่ได้รับข้อมูลส่วนนี้ และยังไม่อ่านคะแนนจนกว่าจะเลือกนักเรียนและบทเรียน

ข้อมูลหน้าแรกใช้ครั้งเดียวในหน่วยความจำ ไม่เก็บลง localStorage และล้างเมื่อออกจากระบบหรือเริ่ม Login ใหม่ การเปิดหน้าครูใหม่และปุ่มโหลดห้องใหม่ยังอ่านสิทธิ์ล่าสุดจากเซิร์ฟเวอร์ การเปลี่ยนห้อง ค้นหา และแบ่งหน้ายังตรวจสิทธิ์ทุกคำขอ ฝั่ง Apps Script อ่านหัวตารางและข้อมูลที่มีชนิดข้อมูลในครั้งเดียวต่อชีตต่อคำขอ โดยไม่ใช้ cache สิทธิ์ข้ามคำขอ

หน้าเว็บรองรับ Apps Script รุ่นเดิมที่ไม่ส่งรายชื่อมาพร้อม Login/ตัวเลือกห้อง โดยกลับไปเรียก API รายชื่อเดิม หากต้องการใช้การลดคำขอเต็มรูปแบบ ต้องอัปเดต `Code.gs` ใน deployment เดิมตามขั้นตอนด้านล่างด้วย โค้ดรอบนี้ยังไม่ได้เผยแพร่หรือทดสอบกับ Google deployment จริง ผลทดสอบออนไลน์ที่บันทึกในหัวข้ออื่นเป็นของรุ่นก่อนหน้า

เพิ่มการตรวจกรณีเปลี่ยนบัญชีขณะที่ Login ยังไม่ตอบกลับ การใช้ข้อมูลหน้าแรกเพียงครั้งเดียว ปุ่มลองใหม่หลังโหลดรายชื่อผิดพลาด และการเปลี่ยนคำค้นระหว่างโหลดห้อง เพื่อไม่ให้รายชื่อจากคำค้นเก่าถูกใช้เป็นผลของคำค้นใหม่

ผลตรวจในเครื่องรอบนี้: server/client ผ่าน 17 รายการ, privacy ผ่าน 2 รายการ และ browser หน้าครู/แอดมินผ่านบน desktop 1366px กับมือถือ 375px โดยใช้เว็บและ Code.gs จริงกับชีตจำลอง รวมทั้งตรวจ API รุ่นเดิม การเปิดหน้าใหม่หลังถอนสิทธิ์ และการส่งผลสอบจากหน้านักเรียนเดิม ชุดบัญชี/navigation/Login/Dashboard ผ่านด้วย รายงาน browser อยู่ที่ `tmp/teacher-admin-review/report.json`

## รุ่นหน้าครู–แอดมิน ภาคเรียนที่ 2/2569

ต่อยอดรุ่นที่เชื่อมและทดสอบบน GitHub Pages สำเร็จแล้ว โดยเพิ่มการมอบหมายห้องให้ครูในระบบกลาง วันที่ 24 ตุลาคม 2569 ผู้ใช้ยืนยันว่าอัปเดต Apps Script deployment เดิมแล้ว ทดสอบเว็บ local กับ URL `/exec` เดิมสำเร็จ และผู้ใช้ตรวจอนุมัติหน้าจอสำหรับเผยแพร่แล้ว ดูผลตรวจ local ด้านล่าง ส่วนคำสั่ง preview ยังคงเป็นข้อมูลจำลองสำหรับตรวจหน้าจอโดยไม่แตะชีตโรงเรียน

ก่อนแก้พบว่า `Code.gs` ตรวจบทบาท Teacher/Admin แต่ยังไม่จำกัดห้อง ส่วน `teacher-dashboard.js` โหลดตารางคะแนนรวมและยังไม่มีหน้าจัดการครู ระบบบัญชี 907 คน, session, คิวส่งคะแนน, ID ป้องกันซ้ำ และ latest/best/history มีอยู่แล้ว จึงใช้ระบบเดิมต่อทั้งหมด

### ขั้นตอนเดิมเมื่อติดตั้งรุ่นหน้าครู–แอดมินครั้งแรก

หัวข้อนี้เป็นขั้นตอนติดตั้ง `SLH_Teachers` ครั้งแรก สำหรับอัปเดต performance บนระบบที่ติดตั้งแล้ว ให้ใช้ [ขั้นตอนอัปเดตล่าสุด](apps-script-deployment-update.md) ซึ่งข้าม `setup()` ได้เมื่อผลตรวจครบ

1. เปิด Apps Script **project เดิม** ของชีตที่ใช้งานอยู่ คัดลอก **ทั้งไฟล์** [Code.gs ฉบับเต็ม](../integrations/google-sheets/Code.gs) ไปแทนเนื้อหา `Code.gs` แล้ว Save ไม่ต้องสร้าง project หรือ deployment ใหม่ และไม่ต้องเปลี่ยน `appsscript.json`
2. ไปที่ **Project Settings → Script properties** เพิ่ม `SLH_CURRENT_TERM` เป็น `2` คง `SLH_SPREADSHEET_ID`, `SLH_STUDENTS_SHEET`, `SLH_STAFF_SHEET` เดิม ไม่ลบ properties เดิม
3. รัน **`inspectSetup()`** ก่อน ผลต้องเป็น `ok: true`, `academicYear: "2569"`, `term: "2"`, `studentCount: 907` ฟังก์ชันนี้อ่านอย่างเดียว
4. รัน **`setup()`** หนึ่งครั้งเพื่อเพิ่มชีต `SLH_Teachers` ที่ยังไม่มี และตรวจโครงสร้างชีตระบบเดิม รันซ้ำได้ ไม่ล้าง `SLH_Events`, `SLH_Sessions`, Students, Staff หรือชีตเดิมอื่น ๆ
5. เลือก **Deploy → Manage deployments → เลือก Web app เดิม → Edit (รูปดินสอ) → Version: New version → Deploy** คง Execute as และ Who has access ตาม deployment เดิม วิธีนี้อัปเดตโค้ดโดยรักษา URL `/exec` เดิม ตาม [เอกสาร Google เรื่องการแก้ versioned deployment](https://developers.google.com/apps-script/concepts/deployments)
6. เมื่อเว็บไซต์รุ่นนี้ได้รับอนุมัติและเผยแพร่แล้ว ให้เข้าสู่ระบบด้วย `watcharapon` เปิดแท็บ **จัดการผู้สอน** เพิ่มครูและกำหนดชั้น–ห้องในภาคเรียน 2 ครูใหม่ยังไม่เห็นนักเรียนจนได้รับมอบหมายห้อง `watcharapon` ยังคง Teacher + Admin และอ่านได้ทุกห้อง

หากยังไม่รัน setup หรือยังไม่ตั้งเทอม หน้าครูจะแจ้งให้ตั้งค่าระบบ ส่วน API นักเรียน login/ส่งคะแนนยังคงใช้โครงสร้างเดิม อย่าแก้ URL ใน `sheets-config.js` เพื่อแก้ปัญหานี้ และไม่ต้องเรียก `doPost()` จาก editor

### สิทธิ์ ข้อมูล และการแสดงผล

- `SLH_Teachers` เป็นชีตส่วนตัวเพิ่มเพียงชีตเดียว เก็บชื่อครู สถานะ hash/salt ของรหัสผ่านครูใหม่ และ `AssignmentsJSON` ตามคีย์ `2569:2` การแก้ไขเพิ่มแถวใหม่ โดยใช้ค่าล่าสุด ไม่แก้ Staff/Students และไม่ลบคะแนน
- ครูหนึ่งคนรับหลายห้องได้ และหลายครูรับห้องเดียวกันได้ Admin อ่านทุกห้อง บัญชีหลัก `watcharapon` ปิดจากหน้าแอดมินไม่ได้ ไม่มี API เพิ่ม Admin หรือแก้บัญชีนักเรียน
- ตรวจบัญชีที่ยังเปิดใช้งานและการมอบหมายล่าสุดใน Apps Script ทุกคำขอ รวมทั้ง API `teacherSummary` เดิม การยกเลิกห้องหรือปิดครูจึงมีผลในการเรียกครั้งถัดไป แม้ใช้ token เดิม ไม่มี cache สิทธิ์ใน browser
- หน้าเลือกชั้น → ห้อง โหลดรายชื่อครั้งละ 25 คน เรียงเลขที่ ค้นหาชื่อ/Username ได้ แล้วโหลดคะแนนเฉพาะนักเรียนและบทเรียนที่เปิด ประวัติสอบแบ่งครั้งละ 10 รายการ ปุ่มลองใหม่ไม่แตะคิวคะแนนนักเรียน
- ผลคะแนนเดิมมีปีการศึกษาแต่ไม่มีข้อมูลภาคเรียน จึงรักษาและแสดง **ผลที่บันทึกทั้งหมดของปี 2569** ไม่จัดผลเก่าเป็นเทอม 2 โดยคาดเดา สิทธิ์ครูใช้ภาคเรียนปัจจุบันเท่านั้น
- ไม่มีกิจกรรม = “ยังไม่ทำ”; มีผลจริง 0 = `0 / คะแนนเต็ม`; มีรายการแต่ฟิลด์หาย = “ไม่มีข้อมูล” ไม่ใช้ 0 แทนค่า missing/null/ค่าว่าง
- Simulation ไม่มีคะแนนหรือเกณฑ์ผ่าน เก็บและแสดง `values`, `metrics`, `summary` ตามจริง แบบจำลอง G1U1L1 เริ่มที่ `t=0` จึงให้การเติบโต 0 หน่วย เมื่อ `t=1, light=6` ได้ 3 หน่วยทั้งสองกลุ่ม ไม่ใช่การอ่านฟิลด์คะแนนผิด สูตรและ engine ไม่เปลี่ยน บางบทไม่มี metrics ตามแบบจำลองเดิม จะแสดงสถานะทำแล้วและ summary โดยไม่เติมเลข 0

### ผลตรวจ local ของรุ่นหน้าครู–แอดมิน

- Server/client/privacy ผ่าน 16 รายการ: ครูห้อง A อ่าน A ได้และ B ไม่ได้ทุก API, ถอนห้องแล้ว token เดิมอ่านไม่ได้, ปิดบัญชีแล้ว login/session ใช้ไม่ได้, Admin อ่านได้ทุกห้อง, รองรับหลายครูต่อห้องและหลายห้องต่อครู, คง source accounts/คะแนน/ประวัติ, latest/best และการกันส่งซ้ำ, missing/null/0 แยกกัน
- Browser ใช้หน้าเว็บจริงและ Code.gs จริงใน VM กับชีตจำลอง 907 บัญชี ผ่านที่ desktop 1366px และมือถือ 375px: รายชื่อ/ค้นหา/แบ่งหน้า, ผลกิจกรรม, ประวัติ 13 ครั้งแบ่งหน้า, เพิ่มครู/ปิดบัญชี/มอบหมายหลายห้อง, retry หลัง error และคิวคะแนนเดิมไม่หาย, นักเรียนยังส่งข้อสอบผ่าน handler เดิมได้
- ตรวจ build 967 ไฟล์ และไฟล์ข้อความ 95 ไฟล์ ไม่รวมข้อมูลบัญชี backend หรือชุดทดสอบใน Pages เทียบไฟล์เปลี่ยนกับรายชื่อ 907 บัญชีและรหัสผ่าน 908 รายการจากไฟล์ต้นทางแบบ in-memory ไม่พบข้อมูลจริงหรือ token ติดไป
- ชุดรักษาหน้า Login/Dashboard ผ่าน รวมการตรวจเนื้อหาและธีมเดิม 990 ไฟล์ `index.html`, assets เนื้อหา/เกม/แบบฝึก/ข้อสอบ/Simulation/ธีม และ URL production ไม่มี diff ในรอบนี้
- Preview Login ทั้งครูและ Admin ผ่าน ไม่มี request ไป Google การทดสอบนี้ยังไม่รับรอง Apps Script รุ่นใหม่บน deployment จริงหรือโหลดพร้อมกัน 907 คน

### ผลตรวจ local กับ Apps Script จริง (24 ตุลาคม 2569)

- ยืนยันปี 2569 ภาคเรียน 2, Teacher/Admin ของบัญชีหลัก และ API รุ่นใหม่ผ่าน URL เดิม
- เพิ่มครูผ่านหน้าแอดมินจริง ครูที่ยังไม่ได้รับมอบหมายห้องอ่านนักเรียนไม่ได้ เมื่อมอบหมายแล้วอ่านรายชื่อ ผลรายบท และประวัติสอบในห้องที่ได้รับสิทธิ์ได้ พร้อมตรวจจอมือถือ 375px
- เรียก roster, studentResults, examHistory และ teacherSummary เดิมสำหรับห้องอื่นถูกปฏิเสธ ครูเรียก API แอดมินไม่ได้ นักเรียนเรียกข้อมูลครู แอดมิน หรือผลของผู้อื่นไม่ได้
- มอบหมายหลายห้องและถอนห้องผ่าน UI สำเร็จ session เดิมของครูถูกปฏิเสธในการอ่านครั้งถัดไปหลังถอนห้อง แอดมินยังอ่านได้ทุกห้อง

## ติดตั้ง Apps Script

1. เปิดชีตใหม่ด้านบน เลือก **Extensions → Apps Script** ที่ผู้ใช้เปิดไว้แล้ว วางเนื้อหาทั้งหมดจาก `integrations/google-sheets/Code.gs` ใน `Code.gs` แล้ว Save หาก project มีโค้ดเดิมที่ใช้งานอยู่ให้เก็บสำเนาไว้ก่อน และตรวจไม่ให้มี `doGet`/`doPost` ชื่อซ้ำ
2. ใน **Project Settings → Script properties → Add script property** ตั้งค่าตารางด้านล่าง ค่าเหล่านี้อยู่ฝั่ง Apps Script ไม่ใส่ใน JavaScript สาธารณะ
3. เลือกฟังก์ชัน `inspectSetup` กด Run และอนุญาตด้วยบัญชีเจ้าของชีต ตรวจ Execution log ว่านักเรียนครบ 907 บัญชี จากนั้นเลือก `setup` แล้วกด Run เพื่อสร้างชีตระบบ ดูรายละเอียดด้านล่าง
4. เลือก **Deploy → New deployment → Web app**, **Execute as: Me**, **Who has access: Anyone** แล้ว Deploy ระบบใช้ username/password ของโรงเรียนตรวจสิทธิ์ภายใน `doPost` การเข้าถึง URL ได้ไม่ได้ทำให้อ่านคะแนนได้เอง หาก Workspace ไม่อนุญาต Anyone ต้องให้ผู้ดูแลเปิด deployment ที่เหมาะสมก่อน ไม่แก้ชีตให้สาธารณะเพื่อข้ามข้อจำกัด
5. คัดลอก **Web app URL** รูปแบบ `https://script.google.com/macros/s/…/exec` มาใส่ `endpoint` ใน `assets/integrations/sheets-config.js` แล้ว build/deploy เว็บไซต์ตาม workflow เดิม URL ของ Google Sheets และ URL `/dev` ใช้แทนไม่ได้
6. เมื่อแก้ Code.gs ภายหลัง ใช้ **Deploy → Manage deployments → Edit → New version → Deploy** โดยใช้ deployment เดิมเพื่อคง URL

### ฟังก์ชันที่ต้องรันครั้งแรก

1. **`inspectSetup()`** — ตรวจหัวคอลัมน์ ชื่อผู้ใช้ซ้ำ จำนวน 907 บัญชี และ Teacher/Admin ของ watcharapon โดยไม่แก้ชีต ผลตรวจใน Execution log มีเฉพาะข้อมูลสรุป ไม่มีรายชื่อหรือรหัสผ่าน
2. **`setup()`** — ตรวจซ้ำก่อนสร้าง `SLH_Events`, `SLH_Sessions` และ `SLH_Teachers` เฉพาะชีตที่ยังไม่มี หากชีตระบบมีอยู่แล้วจะตรวจโครงสร้างและเก็บแถวเดิมไว้ รันซ้ำได้ ไม่ล้างบัญชีหรือผลการเรียน
3. **ไม่ต้องรัน `doPost()` เอง** — เว็บไซต์จะเรียกเมื่อ login/ส่งผล/เปิดข้อมูลครู ส่วน `doGet()` ใช้ตรวจว่า deployment ตอบได้เท่านั้น

หาก `inspectSetup` หรือ `setup` แจ้งหัวคอลัมน์/จำนวนบัญชีผิด ให้ตรวจชื่อชีตและหัวแถวแรก ห้ามลบชีตเดิมเพื่อให้ผ่านการตรวจ

ไม่ต้องใส่รหัสผ่านใน properties, HTML, GitHub Secrets หรือ config เว็บ โค้ดอ่านรหัสผ่านเดิมจากคอลัมน์ส่วนตัวในชีต และไม่ส่งคอลัมน์รหัสผ่านกลับไปยัง client

## การรักษาข้อมูลและขอบเขตผลคะแนน

บัญชีต้นฉบับเป็นแหล่งตรวจ login การเพิ่มชีตภายในระบบไม่แก้ชื่อ รหัสผ่าน บทบาท หรือแถวในชีตเดิม การตั้งค่าซ้ำต้องไม่ล้างผลที่บันทึกแล้ว session มีอายุและเพิกถอนได้ สิทธิ์การดูนักเรียนตรวจจากบัญชีฝั่ง server ทุกคำขอ การแก้ role ใน browser จึงไม่ให้สิทธิ์อ่านชีต

แต่ละผลกิจกรรมมี ID ถาวร คิวส่งซ้ำใช้ ID และเนื้อหาเดิม server ใช้ [LockService](https://developers.google.com/apps-script/reference/lock/lock-service) และตรวจรายการที่บันทึกแล้วก่อนเพิ่มแถว ถ้าพบ ID เดิมที่เนื้อหาเปลี่ยนจะปฏิเสธ การส่งช้าหรือส่งย้อนหลังไม่ควรทับความหมายของคะแนนล่าสุด

ผลเกมเดิมมีการผ่านและจำนวนครั้ง ไม่มีสูตรคะแนนตัวเลขสำหรับทุกชนิดเกม จึงเก็บผลตามที่ engine คำนวณ แบบฝึกเก็บจำนวนถูก/เต็มและผลการตรวจ Simulation เก็บค่าที่ปรับและผลคำนวณ สอบเก็บแต่ละครั้ง คะแนนล่าสุดและคะแนนสูงสุดคำนวณแยกกัน

คะแนนมาจากการคำนวณในเว็บไซต์ผู้เรียนและมีป้าย `clientReported` จึงยังไม่ใช่ข้อสอบที่ตรวจคำตอบบน server ผู้ที่แก้ข้อมูลใน browser อาจส่งผลที่ไม่ตรงการทำจริงได้ การตรวจ login/สิทธิ์และการกันบันทึกซ้ำไม่ได้แก้ข้อจำกัดนี้

ความคืบหน้าและการเรียนต่อยังอยู่ใน browser เดิม ไม่ได้ย้ายไปเครื่องใหม่โดยอัตโนมัติ ไม่ดึงคะแนนจากบัญชีสาธิตไปผูกกับบัญชีจริง ประวัติที่ระบบเก่าเคยตัดเกิน 10 ครั้งไปแล้วไม่สามารถกู้จากเว็บได้ และผลที่เกิดก่อนเปิดการเชื่อมจะไม่ถูกอ้างว่าได้ส่งเข้า Sheets แล้ว

907 บัญชีเป็นจำนวนทะเบียน ไม่ใช่ผลรับรองว่าใช้งานพร้อมกัน 907 คนแล้ว Apps Script มี [โควตาและข้อจำกัดการทำงานพร้อมกัน](https://developers.google.com/apps-script/guides/services/quotas) และการอ่านประวัติจะมากขึ้นตามข้อมูล ต้องทดสอบกับ deployment จริงและติดตาม Apps Script Executions ก่อนใช้งานทั้งโรงเรียน

## สถานะการเชื่อม

ตั้ง URL `/exec` ที่ผู้ใช้ส่งมาใน `assets/integrations/sheets-config.js` แล้ว และวันที่ 23 ตุลาคม 2026 ทดสอบผ่าน Chrome กับ Apps Script ที่ deploy จริง จากเว็บ source ที่เปิดผ่าน local HTTP server สำเร็จ ทั้ง Login นักเรียนสามบัญชี, Teacher/Admin, การปฏิเสธสิทธิ์นักเรียน, การส่งผลกิจกรรมครบทุกประเภท, ประวัติสอบ, คะแนนล่าสุด/สูงสุด และการส่งซ้ำ ผู้ใช้ระบุบัญชีทดสอบก่อนเขียนข้อมูลจริง ผลทดสอบถูกเก็บในบัญชีที่ได้รับอนุญาตเท่านั้น ไม่มีการแก้ไขบัญชีในชีตต้นทาง

รายงานการทดสอบจริงเก็บไว้ที่ `tmp/sheets-live-report.json` ซึ่ง Git ไม่นำไปเผยแพร่ ไม่ใส่ผลคะแนนรายบัญชีในเอกสารหรือ assets สาธารณะ ข้อมูลรับรองอ่านเข้า memory จากไฟล์บัญชีเดิมและไม่ได้บันทึกลงไฟล์เว็บ

ขณะทดสอบ local ข้างต้นยังไม่ได้เผยแพร่รุ่นนี้ขึ้น GitHub Pages การยืนยันรุ่นออนไลน์ต้องอ้างอิง workflow `Deploy Science Learning Hub` ของ commit ที่เผยแพร่ และผลตรวจจากโดเมนจริงใน `tmp/sheets-online-report.json` ส่วนการทดสอบจำนวนผู้ใช้พร้อมกัน 907 คนยังไม่ได้ทำ รหัสผ่านและรายชื่อนักเรียนไม่ได้ถูกคัดลอกลง public assets ไฟล์ source `Code.gs` มีเฉพาะตรรกะ ไม่มีข้อมูลบัญชีจริง และ build เดิมเลือกเฉพาะ `index.html`/`assets` จึงไม่รวม backend หรือไฟล์นำเข้าบัญชีไปกับ Pages

ก่อนเผยแพร่ตรวจ diff เทียบกับข้อมูลในไฟล์บัญชีเดิมแบบ in-memory โดยไม่บันทึกข้อมูลนั้นลง repository และนำ directory/รหัสผ่านสาธิตเดิมออกจากโค้ดเว็บด้วย ข้อมูลสาธิตอยู่เฉพาะ `tests/offline-sheets-fixture.mjs` ซึ่งไม่ถูก build ไปกับ Pages; compatibility identifier ของ localStorage เดิมยังคงไว้

## ผลทดสอบในเครื่อง (23 ตุลาคม 2026)

- Server 8 tests ผ่าน: บัญชีจำลอง 907 รายการ, ตรวจและตั้งค่าซ้ำโดยไม่เปลี่ยนต้นทาง, session/สิทธิ์/หมดอายุ/logout, ส่งซ้ำ/ชน ID, ประวัติสอบ 17 ครั้งและผลส่งย้อนหลัง, validation ทุกประเภท, rate limit และ payload ที่สร้างจาก handler เว็บจริงครบทั้ง 9 กิจกรรม
- Client ผ่าน: ID คงเดิมหลัง retry/reload, รับผลยืนยันบางส่วน, เปลี่ยนบัญชีขณะส่ง, หลายแท็บ, session หมดอายุ, timeout และพื้นที่จัดเก็บเต็ม
- Privacy 2 tests ผ่าน: ตรวจ config ที่มีเฉพาะ endpoint และ build 967 ไฟล์ (text 95 ไฟล์) พร้อมตรวจ scripts/styles และลำดับโหลดตรงกับ source
- Browser ผ่านบน Chrome ที่ 1366px และ 375px: login จริงของหน้าเว็บโดยจำลอง API, filters ทั้งสี่, pagination, ประวัติสอบเกิน 10 ครั้ง, latest/best, ป้องกัน HTML injection, ซ่อนข้อมูลครูจากนักเรียน และส่งผลสอบครบ 20 คำตอบ ไม่มี page error
- Regression เดิมผ่าน: บัญชี/localStorage, navigation, เกม 120 ชุด, แบบฝึก 120 ชุด, O-NET, final exam/migration, simulation/native models/plant growth, readiness, formulas และการรักษาหน้า Login/Dashboard

ปรับ assertions ของงานดีไซน์เก่าที่เคยห้ามเปลี่ยนโค้ดนอกหน้าตนนั้น ให้ตรวจเนื้อหาและรูปแบบเดิมโดยตรงและยอมรับเฉพาะ hooks ที่อนุญาตในงานนี้ อัปเดต hash ของ simulation engine สำหรับการส่งผลเท่านั้น; fixtures ของโมเดลวิทยาศาสตร์และเนื้อหายังคงเดิม ผลในหัวข้อทดสอบในเครื่องนี้ใช้ข้อมูลจำลอง ส่วนการทดสอบ Google deployment จริงระบุแยกในหัวข้อสถานะการเชื่อม

เมื่อกำหนด endpoint จริงแล้ว ชุด VM regression ใช้ config ออฟไลน์เฉพาะใน harness เพื่อป้องกันการส่งข้อมูลทดสอบเข้าโรงเรียน ชุด `deployment-browser.mjs` ใช้ `tests/offline-sheets-fixture.mjs` ปิดกั้น hosts ของ Apps Script และผ่านการตรวจ subpath, Login/Dashboard, ภาพ, 3D และการเรียนต่อ ชุด browser รุ่นเก่าอื่นที่ใช้บัญชีสาธิตต้องใช้ fixture นี้ก่อนเปิดหน้า ไม่ควรรันบัญชี demo กับ endpoint จริง

```powershell
node --test tests/google-sheets-server.test.mjs tests/google-sheets-client.test.mjs tests/google-sheets-privacy.test.mjs
node tests/google-sheets-browser.mjs
```

คำสั่ง browser ใช้ Playwright และ Chrome ที่ติดตั้งไว้แล้ว ใน workspace นี้ Node ที่ใช้ตรวจคือ `tmp/browser-check/playwright/driver/node.exe` โดยไม่ได้ติดตั้ง dependency ใหม่
