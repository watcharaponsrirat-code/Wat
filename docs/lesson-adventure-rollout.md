# Premium Voxel Adventure — ธีมบทเรียนกลาง

14 ตุลาคม 2026 · ขยายจากหน้าอ่านต้นแบบไปยังทุกบทเรียนและทุกกิจกรรมในข้อมูลเดิม

## สาเหตุและวิธีแก้

ธีมก่อนหน้านี้เปิดใช้ผ่าน `.readingMode:has(#reading-G1U1L1S1)` จึงครอบคลุมเฉพาะหน้าอ่านของบท “เรียนรู้วิทยาศาสตร์อย่างไร” ขณะที่กิจกรรมอื่นใช้ CSS ของตนเอง และข้อสอบมีข้อกำหนดความกว้างแยกต่างหาก

เปลี่ยนจุดเปิดใช้เป็น `.shell:has(> .stageHUD)` ซึ่งเป็นโครงสร้างร่วมที่ renderer เดิมสร้างให้ทุกบทและทุกกิจกรรม ใช้ CSS tokens `--va-*` ชุดเดียวกัน โดยไม่ต้องเพิ่มเงื่อนไขตาม Lesson ID ไม่คัดลอกหน้า และไม่เพิ่ม JavaScript หรือ DOM wrapper

พื้นหลัง ป้ายไม้ หัวข้อจากข้อมูลเดิม ความก้าวหน้า และแถบกิจกรรม 10 ช่องจึงตามหน้าที่เปิดโดยอัตโนมัติ ข้อสอบใช้ความกว้างของ shell เดียวกับกิจกรรมอื่น ส่วนพื้นที่ทดลอง กระดานเกม และโจทย์ยังคงโครงสร้างเดิม

## สิ่งที่รักษาไว้

- `index.html` ตรงกับ baseline หลังตัดเฉพาะ stylesheet links ที่เพิ่มและการเปลี่ยน version; ข้อมูล เนื้อหา โครงสร้าง HTML และโค้ดแอปเดิมไม่เปลี่ยน
- ไม่แก้ไฟล์เนื้อหา ภาพ/infographic คำถาม เฉลย เกม Simulation สูตรคำนวณ บัญชีผู้ใช้ API, routing, IDs หรือ schema ความก้าวหน้า
- ปุ่มและสถานะทั้งหมดอิงข้อมูลเดิม แถบกิจกรรมคง 10 ช่องและลำดับเดิม
- ใช้พื้นที่วาด 3D, canvas, SVG 2D และขนาดภาพโจทย์จากระบบเดิม ไม่เปลี่ยนการซ่อน/เปิดไพ่หรือเรขาคณิตกระดานเกม
- รูปลักษณ์หน้าอ่านต้นแบบผ่านการเทียบ computed styles และ pseudo styles แบบตรงกันที่ 390×844 และ 1366×768

## ผลทดสอบจริง

Chrome: **40 บท × 10 กิจกรรม × 7 ขนาด = 2,800 กรณี** ผ่านทั้งหมด

ขนาด: 375×812, 390×844, 430×932, 768×1024, 1280×720, 1366×768 และ 1440×900

- เปรียบเทียบ DOM เนื้อหาและชื่อ/สถานะกิจกรรม **400 หน้า** กับ baseline ตรงกัน โดยยกเว้นเฉพาะ output ภายใน viewport ของ renderer 3D ที่สร้างขณะทำงานและขึ้นกับขนาดจอ
- สถานะบทเรียนเดิม **400 ครั้ง** ตรงกัน; normalize เฉพาะ timestamp ในการเปรียบเทียบ
- ภาพวิทยาศาสตร์ในหน้าอ่าน **302 ภาพ** โหลดสำเร็จและแสดงแบบรักษาสัดส่วน
- ไม่พบ horizontal page overflow, ข้อความ/ปุ่มที่ตรวจล้นกรอบ หรือแถบกิจกรรมบังเนื้อหา ปุ่มกิจกรรมมีขนาดอย่างน้อย 44×44 CSS pixels
- ไม่พบ JavaScript error หรือ local resource error ในชุดตรวจ
- ชุด regression เดิมทั้ง 10 ชุดจาก Pages workflow ผ่าน: account, navigation, game, O-NET, final exam, exam migration, simulation, native models, readiness และ formula
- Static build และ deployment regression ผ่าน ตรวจลำดับและ byte equality ของ script/CSS รวมถึงไฟล์ที่อ้างอิงใน build
- Playwright WebKit ผ่าน 40 หน้า: 4 บทตัวแทน × 10 กิจกรรม ที่ 390×844 รวม “สมบัติของสารบริสุทธิ์”; ไม่ใช่การทดสอบบน iPhone จริง

ชุดใช้งานจริง `--flows` ผ่านเพิ่มเติม:

- ปรับ controls **84 ตัว** ครบ Simulation ของทั้ง 40 บท พร้อม reset และสลับ 2D/3D เทียบค่ากับ baseline
- กดแถบกิจกรรมทั้ง 10 ช่อง ปุ่มอ่านจบ → ทดลอง ปุ่มย้อนกลับและเรียนต่อ
- ทำเกม 1–3 และแบบฝึกหัดครบ 3 ระดับในบท G1U1L1 ตรวจ feedback ผิด/ถูก/สำเร็จ และรูปแบบผลลัพธ์ที่ 7 ขนาดจอ
- โหลดภาพและเลือกคำตอบผิด/ถูกของ O-NET ต้นฉบับทั้ง **66 ข้อ**
- ส่งข้อสอบจริงได้ **55% (ไม่ผ่าน), 60% (ผ่าน), 100% (เต็ม)** ป้องกันการส่งไม่ครบ สลับข้อเมื่อทำใหม่ และแสดงรางวัลตามผลจริง
- เปรียบเทียบ DOM/feedback เพิ่ม **142 ครั้ง** และสถานะ/ข้อมูลบันทึกเพิ่ม **279 ครั้ง** ตรงกับ baseline
- reload → login → resume กลับผลลัพธ์เดิม; หน้า login/dashboard/เลือกชั้น/หน่วย/บทเรียนยังมี computed styles เดิม
- Keyboard focus, Enter/Space และ `prefers-reduced-motion` ผ่าน; ไม่พบ JavaScript หรือ local resource error

ในการเปรียบเทียบใช้ลำดับสุ่มเดียวกันระหว่าง baseline/ปัจจุบันสำหรับแต่ละการกระทำ และเปลี่ยน seed ระหว่างการทำข้อสอบซ้ำ เพื่อทดสอบการสลับข้อได้โดยไม่แก้โค้ดแอป

หลักฐาน: `tmp/lesson-adventure-review/report.json`, `flows.json`, `webkit.json` และ `tmp/lesson-adventure-regressions.json`

## รันตรวจซ้ำ

```powershell
node tests/lesson-adventure-browser.mjs
node tests/lesson-adventure-browser.mjs --flows
```

ใช้ Playwright และ Chrome ที่ติดตั้งไว้แล้วกับ browser profiles ชั่วคราว ไม่แตะข้อมูลนักเรียนใน browser จริง การทดสอบใช้ baseline Git commit จึงต้องมี commit ดังกล่าวในประวัติ local

`tests/reading-adventure-browser.mjs` เป็นชุดตรวจของต้นแบบรอบแรก ซึ่งตั้งใจยืนยันว่าบทอื่นยังไม่รับธีม; ใช้ชุดตรวจ global ข้างต้นสำหรับรอบนี้

ยังไม่ได้ตรวจบนอุปกรณ์ iPhone/Android จริงหรือ Firefox การผ่าน layout ครบทุกบทไม่เท่ากับการตรวจความถูกต้องของหลักสูตรใหม่ เนื้อหาและสูตรทั้งหมดคงเดิม

การเผยแพร่ใช้ repository เดิมผ่าน `origin/main` และ Pages workflow เดิม ตามคำขอให้อัปโหลด GitHub ก่อนหน้า เอกสารนี้บันทึกผลตรวจใน workspace; commit และผลเผยแพร่รายงานในสรุปส่งมอบ
