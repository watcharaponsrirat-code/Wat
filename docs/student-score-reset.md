# รีเซ็ตผลนักเรียนรายคน — 26 ตุลาคม 2569

สถานะก่อนเผยแพร่หน้าเว็บ: Apps Script deployment จริงรองรับรุ่นรีเซ็ตแล้ว ผู้ใช้ยืนยันว่ารัน `setup()` และพบ `SLH_Resets` จาก `inspectSetup()` การทดสอบหน้าเว็บรุ่นใหม่กับหลังบ้านจริงผ่านทั้งนักเรียนและแอดมิน ยังไม่ได้รีเซ็ตข้อมูลนักเรียนจริง

ใช้ [Code.gs ล่าสุด](../integrations/google-sheets/Code.gs) สำหรับรอบนี้ ไฟล์ `tmp/apps-script-update-20261025/Code.gs` ที่เปิดค้างอยู่เป็นสำเนารุ่น performance เดิม ไม่มีคำสั่งรีเซ็ต สำเนาใหม่อยู่ที่ `tmp/apps-script-reset-20261026/Code.gs`

## สิ่งที่แอดมินทำได้

ใน **ผลนักเรียน → เลือกนักเรียน → เลือกบทเรียน → รีเซ็ตคะแนนนักเรียนคนนี้** เลือกเฉพาะบทเรียนที่แสดงหรือทุกบทเรียนของนักเรียนคนนั้น แล้วพิมพ์ Username ให้ตรงก่อนยืนยัน แอดมินเลือกบทเรียนต่างชั้นได้ด้วยเพื่อจัดการผลจากการทบทวนหรือเรียนล่วงหน้า ครูทั่วไปและนักเรียนไม่มีสิทธิ์รีเซ็ต แม้เรียก API โดยตรง

ขอบเขตครอบคลุมผลเกม แบบฝึก O-NET Simulation สอบท้ายบท/ประวัติสอบ และความคืบหน้า/XP ในบทเรียนที่เลือกของปี 2569 การรีเซ็ตทุกบทไม่ได้หมายถึงทุกคนหรือทั้งห้อง นักเรียนคนอื่นและบัญชีเดิมไม่เปลี่ยน

ระบบเพิ่มบันทึกใน `SLH_Resets` ว่าใครรีเซ็ตนักเรียนคนใด บทใด และเมื่อใด ข้อมูลกิจกรรมเดิมยังอยู่ใน `SLH_Events` สำหรับตรวจสอบ แต่ไม่นับหรือแสดงในผลปัจจุบันหลังรีเซ็ต การส่งคำขอเดิมซ้ำจะไม่รีเซ็ตคะแนนใหม่ที่ทำภายหลัง

เมื่อนักเรียนเข้าสู่ระบบ ส่งผลกิจกรรม กลับมาที่แท็บ/ออนไลน์ หรือตรวจสถานะทุก 60 วินาทีขณะหน้าเปิดอยู่ เว็บจะรับสถานะรีเซ็ตจากเซิร์ฟเวอร์ คิวเก่าของบทที่รีเซ็ตจะถูกตัดออกโดยไม่ส่งกลับเป็นคะแนนใหม่ ความคืบหน้าเริ่มในพื้นที่เก็บรุ่นใหม่ ส่วนบทอื่นคงเดิม ถ้านักเรียนกำลังทำบทที่ถูกรีเซ็ต หน้าจะกลับหน้าแรกพร้อมแจ้งเตือน ต้องออนไลน์จึงรับสถานะล่าสุดได้

## อัปเดต Apps Script ก่อนเผยแพร่เว็บรุ่นนี้

1. เปิด **โปรเจกต์ Apps Script เดิม** ของชีตที่ใช้อยู่ เก็บเลข version ปัจจุบันไว้ คัดลอกทั้งไฟล์จาก `tmp/apps-script-reset-20261026/Code.gs` ไปแทน `Code.gs` แล้ว Save
2. คง `SLH_SPREADSHEET_ID`, `SLH_CURRENT_TERM=2`, ชื่อชีตต้นทาง, `SLH_READY` และ manifest เดิม รัน **`inspectSetup()`** ต้องได้ `ok:true`, `studentCount:907`, `academicYear:"2569"`, `term:"2"`, `sourceTabsModified:false`
3. รัน **`setup()` หนึ่งครั้ง** เพื่อเพิ่ม `SLH_Resets` และตั้ง `SLH_RESETS_READY=1` อัตโนมัติ รุ่นนี้ต้องเพิ่มชีต จึงต่างจากรุ่น performance วันที่ 25 ที่ไม่ต้องรัน setup ซ้ำ ฟังก์ชันไม่ล้างคะแนนหรือแก้ Students/Staff
4. รัน **`inspectSetup()`** อีกครั้ง ต้องมี `SLH_Events`, `SLH_Sessions`, `SLH_Teachers`, `SLH_Resets` ใน `existingAppTabs`
5. ไป **Deploy → Manage deployments → เลือก deployment ที่ URL ตรงกับ [sheets-config.js](../assets/integrations/sheets-config.js) → Edit → New version → Deploy** คงสิทธิ์ Execute as/Who has access เดิม การอัปเดต version ใน deployment เดิมคง URL ได้ตาม [เอกสาร Google](https://developers.google.com/apps-script/concepts/deployments#edit_a_versioned_deployment)
6. เปิด URL `/exec` ตรวจว่าตอบ `capabilities.adminResetStudent:true` ซึ่งยืนยันว่ารุ่นโค้ดรองรับ API ใหม่ แต่ผลนี้เพียงอย่างเดียวยังไม่ยืนยันว่า setup และการเข้าสู่ระบบผ่าน
7. แจ้งว่าอัปเดตแล้วพร้อมผลสรุป `inspectSetup()` เพื่อทดสอบการเชื่อมต่อแบบอ่านอย่างเดียวและเผยแพร่ frontend ที่ตรงกันต่อ ไม่ต้องส่งรหัสผ่านหรือรายชื่อนักเรียน

ก่อนใช้งานรีเซ็ตจริง ให้ผู้ใช้โหลดเว็บรุ่นใหม่และเข้าสู่ระบบใหม่ หากยังมี deployment เก่าที่เข้าถึงชีตเดียวกัน ต้องอัปเดต deployment นั้นให้เป็นรุ่นนี้หรือหยุดใช้งานด้วย เพราะโค้ดเก่าจะยังแสดงผลก่อนรีเซ็ตได้ ห้ามย้อนกลับไป backend รุ่นที่ไม่รู้จักประวัติรีเซ็ตหลังเริ่มรีเซ็ตจริง

อย่าลบ/แก้ลำดับแถวใน `SLH_Resets` หรือเคลียร์ `SLH_RESETS_READY` ถ้าชีตนี้หายหลังติดตั้ง ระบบจะปฏิเสธการอ่าน/ส่งผล และ `setup()` จะไม่สร้างประวัติเปล่าทดแทน ต้องกู้คืนชีตเดิมเพื่อรักษาขอบเขตคะแนน

## การตรวจสอบ

ผลรอบนี้ผ่าน: regression เดิม 11 คำสั่ง, unit tests 61 รายการ, build และ deployment regression, browser หน้าครู/แอดมินเดิมรวมเส้นทางรีเซ็ตจนทำข้อสอบใหม่ และ browser ตรวจฟอร์มรีเซ็ตเฉพาะทาง ภาพยืนยัน desktop/375px อยู่ใน `tmp/teacher-admin-review/reset-form-*.png` รายงานรวมอยู่ที่ `tmp/apps-script-reset-20261026/manifest.json` และ `verification.json`

การสร้างเว็บครั้งแรกหยุดเพราะ `_site` เดิมมีอยู่แล้ว จึงเก็บไฟล์นั้นไว้และสร้างใหม่สำเร็จที่ `tmp/apps-script-reset-20261026/site` ไม่ใช่ข้อผิดพลาดของโค้ดรุ่นใหม่

หลังผู้ใช้อัปเดต deployment เดิม ตรวจ GET ได้ `ok:true`, service และ protocol 1 พร้อม `capabilities.adminResetStudent:true` แล้ว ทดสอบหน้าเว็บที่เตรียมเผยแพร่กับ API จริงผ่าน: Login นักเรียนพร้อมสถานะรีเซ็ต, `studentResetState`, Login แอดมินพร้อมรายชื่อหน้าแรก, โหลดห้องใหม่, อ่านผลนักเรียน, ประวัติสอบ และรายชื่อผู้สอน ฟอร์มรีเซ็ตเปิด เลือกบทเดียว/ทุกบท และยกเลิกได้ทั้ง 1366px และ 375px โดยไม่มีคำขอ API จากฟอร์ม

รายงาน `tmp/apps-script-reset-20261026/live-local-20261026-01.json` ยืนยันไฟล์หน้าเว็บและทรัพยากรที่โหลดตรงกับ build ไม่มี browser/network error และออกจากระบบทดสอบครบทั้งสอง session ตัวตรวจบล็อก `sync`, `adminResetStudent`, `adminCreateTeacher` และ `adminUpdateTeacher` จึงไม่มีการเขียนคะแนน รีเซ็ต หรือแก้บัญชีครูระหว่างทดสอบ การยืนยันว่ามีชีตรีเซ็ตมาจากผลตรวจของผู้ใช้ ไม่ได้อนุมานจาก GET หรือ Login เพียงอย่างเดียว

SHA-256 ของ `Code.gs` ที่เตรียมไว้: `8eeabba89ef79a3102f2dd1063892f250f6400f87934031980645c55bf203bfe`

การทดสอบคำสั่งรีเซ็ตใช้ข้อมูลจำลองเท่านั้น ครอบคลุมสิทธิ์แอดมิน การยืนยันรายคน บทเดียว/ทุกบท การไม่กระทบคนอื่น การ retry หลังเกิดคะแนนใหม่ คิวออฟไลน์ รุ่นข้อมูลเก่าที่ตอบกลับช้า การเปิดหลายแท็บ ความคืบหน้าเดิม/กิจกรรมที่เปิดค้าง และฟอร์มแอดมินบนหน้าจอ desktop กับมือถือ ส่วน deployment จริงตรวจเฉพาะการเข้าสู่ระบบและอ่านข้อมูล ผลเหล่านี้ไม่ใช่การทดสอบความเร็วหรือจำนวนผู้ใช้งานพร้อมกันบน Google

API ใหม่: `adminResetStudent` รับ `{requestId,studentId,lessonId,confirmStudentId}` โดย `lessonId:""` หมายถึงทุกบทของคนที่เลือกเท่านั้น; `studentResetState` รับ payload ว่างและคืนสถานะของนักเรียนเจ้าของ session เท่านั้น ผล login นักเรียนและ sync ส่ง `resetState` ด้วย เก็บ token ในหน่วยความจำตามเดิม ไม่ใส่ข้อมูลบัญชีหรือคะแนนลงไฟล์เว็บไซต์
